# 算法研发规范 v1（chongqing_prj）

本文与仓库代码同步维护；变更时间切分或评估口径须同时改 [`src/experiment/splits.py`](../src/experiment/splits.py) 与 [`src/metrics/`](../src/metrics/)。

## 1. 三条原则

1. **可复现**：同一 commit + 同一实验配置（[`experiments/`](../experiments/) YAML）+ 同一数据版本（[`dataset_meta.json`](../dataset_meta.json)）应能复现指标与预测文件。
2. **可横向比较**：统一数据产物、统一时间切分（仅 [`splits`](../src/experiment/splits.py) 定义）、统一评估入口（[`evaluate_model_predictions`](../src/metrics/evaluate.py)）。
3. **特征与数据资产化**：ETL/特征以 [`src/pipeline.py`](../src/pipeline.py)、[`src/feature_engineering.py`](../src/feature_engineering.py) 等为入口；禁止在私有脚本中复制一份特征逻辑长期分叉。

## 2. 目录约定

| 路径 | 用途 |
|------|------|
| `source_data/` | 原始数据（只读） |
| `output/` | 流水线默认产物（`dws_hourly_features.csv`、`feature_*.csv` 等） |
| `output/experiments/<id>/` | **每个实验的唯一完整产物目录**，包含 `da_result.csv`、`metrics.json`、`plots/`、模型权重等 |
| `experiments/*.yaml` | 实验配置定义（输入，不属于产物） |
| `src/experiment/` | 切分与实验公共逻辑 |
| `src/metrics/` | 附录标准评估实现 |

> **注意**：`outputs/` 目录已废弃，不再使用。`config_resolved.yaml` 是实验的配置快照，不写入产物目录。

## 3. 工作流程

1. **新建实验**：复制 `experiments/_template.yaml`，填写 `experiment_id`、`runner`、`target`（如 `clearing_da` / `settlement_da`）。
2. **运行**：`python run_experiment.py --config experiments/<name>.yaml`
3. **评估**：训练结束自动在 `output/experiments/<id>/metrics.json` 生成标准评估结果；亦可手动 `python run_eval_standard.py <path/to/preds.csv> ...`
4. **可视化**：对预测明细 CSV 使用统一脚本生成分周曲线与**附录分场景**叠图（默认）：`python run_experiment_viz.py <da_result.csv> --label <名称> [--out-dir <dir>]`；旧版选日加 `--mode legacy`（实现见 [`src/experiment/visualization.py`](../src/experiment/visualization.py)）。
5. **合并前**：在 PR 描述中附上本次实验的 `metrics.json` 路径或关键指标；禁止私自修改 `splits` 而不更新文档与评审记录。

## 4. PR / Code Review 检查项

- [ ] 是否新增「私有」评估指标实现？（应扩展 `src/metrics/`）
- [ ] 是否硬编码新的 `TRAIN_END` / `TEST_START`？（应只用 `src.experiment.splits`）
- [ ] 新模型是否产出可评估的预测明细（`ts` + `actual` + `predicted` 或等价列）？
- [ ] 实验是否可通过 YAML + `run_experiment.py` 复跑（或说明例外原因）？

## 5. 禁止项

- 长期在不同 fork 上开发且不同步 main。
- 随机时间切分或与 `splits` 不一致的切分用于对外汇报对比。
- 复制粘贴 MAE/RMSE/shape 公式到业务脚本而不走 `evaluate_model_predictions`。

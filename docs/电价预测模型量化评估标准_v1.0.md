# 电价预测模型量化评估标准 v1.0

## 1. 文档目的

为统一公司内部电价预测模型的评估口径，避免仅以 MAE 等单一误差指标判断模型优劣，建立一套能够同时反映价格水平、日内曲线形状、关键峰谷结构以及异常场景稳定性的量化评估标准。

本标准适用于：

- 日前电价预测模型（DA）
- 实时电价预测模型（RT）
- 单点预测模型
- 多步曲线预测模型
- 基于机器学习、深度学习、规则融合或集成的预测模型

## 2. 适用原则

电价预测模型评估必须遵循以下原则：

### 2.1 不以单一误差指标作为最终依据

MAE、RMSE 等点误差指标只能反映价格数值偏差，不能充分反映预测曲线是否具备业务可用性。

### 2.2 曲线结构优先于局部点值最优

对于 DA/RT 日内曲线预测，模型是否能够正确表达：

- 日均价格中枢
- 日内起伏轮廓
- 峰谷相对位置
- 振幅大小
- 关键时段高低排序

比单个小时误差更能决定业务价值。

### 2.3 必须分场景评估

总体指标必须结合不同市场状态下的表现进行分析，包括：

- 典型日
- 高波动日
- 异常日 / 极端日
- 低价周 / regime shift 日
- 周末 / 节假日

### 2.4 模型评价应服务业务决策

本标准不仅用于离线技术比较，也用于判断模型是否能够支撑：

- 电价研判
- 交易策略
- 储能充放决策
- 风险预警
- 调度辅助分析

## 3. 评价体系总框架

模型评价分为四层：

| 层级 | 名称 | 含义 |
|------|------|------|
| 第一层 | Level 误差 | 衡量预测曲线整体价格水平是否正确 |
| 第二层 | Shape 相似度 | 衡量预测曲线日内轮廓是否与真实曲线相似 |
| 第三层 | Structure 结构正确性 | 衡量峰谷、振幅、关键块段排序和拐点等结构性特征是否合理 |
| 第四层 | Robustness 稳健性 | 衡量模型在高波动、异常和市场切换场景下是否仍然可用 |

## 4. 核心指标定义

### 4.1 主指标

主指标用于模型正式评审、版本对比和综合排名。

#### 4.1.1 MAE

**定义：** 逐时点绝对误差平均值。

\[
\mathrm{MAE} = \frac{1}{N} \sum_{i=1}^{N} \left| \hat{y}_i - y_i \right|
\]

**作用：**

- 衡量总体价格数值偏差
- 作为基础误差指标保留

**局限：**

- 容易奖励「保守平线」
- 对曲线形状不敏感

#### 4.1.2 Profile Correlation

**定义：** 按天计算预测 24 点曲线与真实 24 点曲线的 Pearson 相关系数，再对所有天取平均。

**作用：**

- 衡量整日曲线轮廓相似度
- 是评价 shape 的核心指标

**解释：**

- 越高越好
- 比 MAE 更接近「预测曲线是否像真实曲线」

#### 4.1.3 Negative-Correlation Day Ratio

**定义：** 按天统计 `profile_corr < 0` 的天数占比。

**作用：**

- 识别「走势整体画反」的严重错误
- 是比平均相关性更重要的安全指标

**解释：**

- 越低越好
- 对 RT 尤其重要

#### 4.1.4 Amplitude Error

**定义：** 按天比较预测曲线与真实曲线的振幅差异。

\[
\mathrm{AmpErr} = \left| \bigl(\max(\hat{y}) - \min(\hat{y})\bigr) - \bigl(\max(y) - \min(y)\bigr) \right|
\]

（按日计算后，再按文档约定做汇总，例如取平均。）

**作用：**

- 衡量曲线是否被压平或过度放大
- 是判断模型是否真正学到日内波动的重要指标

#### 4.1.5 Direction Accuracy

**定义：** 逐小时比较相邻时刻价格差分方向是否一致。

\[
\mathrm{DirectionAcc} = \frac{1}{T-1} \sum_t \mathbf{1}\left\{ \mathrm{sign}(\hat{y}_t - \hat{y}_{t-1}) = \mathrm{sign}(y_t - y_{t-1}) \right\}
\]

**作用：**

- 衡量曲线上升/下降趋势是否判断正确
- 反映模型对走势方向的把握能力

### 4.2 辅助指标

辅助指标用于诊断模型问题、分析结构缺陷，不一定作为主排序指标。

#### 4.2.1 RMSE

**作用：**

- 对大误差更敏感
- 补充 MAE 对极端误差不敏感的问题

#### 4.2.2 Normalized Profile MAE

**定义：** 对每日 24 点曲线做标准化后再计算 MAE。

**作用：**

- 剥离 level 影响后，只比较曲线形状
- 用于判断 shape 是否本质上正确

#### 4.2.3 Peak Hour Error

**定义：** 预测峰值时刻与真实峰值时刻的偏差小时数。

**作用：** 判断高价时段位置是否正确。

#### 4.2.4 Valley Hour Error

**定义：** 预测谷值时刻与真实谷值时刻的偏差小时数。

**作用：** 判断低价时段位置是否正确。

#### 4.2.5 Turning Point Match Rate

**定义：** 预测曲线与真实曲线在拐点位置上的匹配程度。

**作用：**

- 判断关键转折是否被模型捕捉
- 用于评价 shape 的局部结构质量

### 4.3 决策型指标

决策型指标用于判断模型是否具备实际业务可用性。

#### 4.3.1 Peak Block Mean Error

对上午峰、晚峰等关键峰段计算块均价误差。

**作用：** 更贴近交易和报价决策，比逐点误差更稳定。

#### 4.3.2 Valley Block Mean Error

对凌晨谷段、中午低谷段计算块均价误差。

**作用：** 更贴近充电、低价识别和风险预警场景。

#### 4.3.3 Block Rank Accuracy

**定义：** 比较不同块段均价排序是否一致。

例如：晚峰是否高于午间、谷段是否低于平段。

**作用：** 衡量关键块段结构排序是否正确。

#### 4.3.4 Extreme-Day Performance

按异常日、极端低价日、高波动日分别统计上述主指标。

**作用：**

- 防止模型只在普通日表现良好
- 判断模型对风险场景的适应性

## 5. 分层场景定义

为保证评估结果具备解释性，所有主指标必须按以下场景分层统计。

### 5.1 典型日

**定义建议：**

- 日振幅位于历史中间区间
- 无极端高价或低价
- 无明显异常跳变

**作用：** 评价模型基本预测能力。

### 5.2 高波动日

**定义建议：**

- 日振幅高于历史 P75 或 P80，或
- 日内标准差高于历史高分位

**作用：** 评价模型在重要波动场景下是否仍能保有 shape。

### 5.3 异常日 / 极端日

**定义建议：**

- 出现近零价、极端 spike、深谷，或
- 日均价明显偏离近期中枢，或
- 存在明显 regime shift

**作用：** 评价模型在最关键风险场景下是否崩溃。

### 5.4 周末 / 节假日

**定义建议：**

- 周六、周日
- 节假日及节假日前后边界日

**作用：** 评价时间语义变化对模型的影响。

## 6. DA 与 RT 的评价重点差异

### 6.1 DA 模型评价重点

对 DA 模型，评价优先级建议为：

1. Profile Correlation  
2. Negative-Correlation Day Ratio  
3. Amplitude Error  
4. MAE  
5. Peak/Valley Timing  

**解释：**

- DA 更关注整日轮廓和峰谷结构
- 曲线是否「像第二天真实曲线」比逐点误差更重要

### 6.2 RT 模型评价重点

对 RT 模型，评价优先级建议为：

1. Negative-Correlation Day Ratio  
2. Amplitude Error  
3. Profile Correlation  
4. MAE  
5. 风险日 / 炸点日分组表现  

**解释：**

- RT 波动更强、异常更多
- 首先要防止「方向整体画反」和「风险时段乱放大」
- MAE 仍保留，但不能独立主导评估

## 7. 模型合格标准建议

为便于模型版本管理，建议设定「不合格 / 可用 / 优秀」三级标准。

### 7.1 DA 模型建议标准

**不合格** — 满足任一：

- `profile_corr < 0.20`
- `neg_corr_day_ratio > 0.40`
- 振幅长期明显被压平
- 高波动日整体失真

**可用** — 建议达到：

- `profile_corr >= 0.35`
- `neg_corr_day_ratio <= 0.25`
- `direction_acc >= 0.55`
- `amplitude_err` 可控
- 典型日和高波动日仍保持正相关

**优秀** — 建议达到：

- `profile_corr >= 0.45`
- `neg_corr_day_ratio <= 0.15`
- `direction_acc >= 0.58 ~ 0.60`
- `amplitude_err` 明显优于基线
- 峰谷位置和块段排序基本合理

### 7.2 RT 模型建议标准

**不合格** — 满足任一：

- `profile_corr < 0.05`
- `neg_corr_day_ratio > 0.45`
- 风险时段经常画反
- 高波动日表现明显崩溃

**可用** — 建议达到：

- `profile_corr >= 0.15 ~ 0.20`
- `neg_corr_day_ratio <= 0.35`
- `direction_acc >= 0.52`
- `amplitude_err` 明显优于保守平线模型

**优秀** — 建议达到：

- `profile_corr >= 0.25`
- `neg_corr_day_ratio <= 0.25`
- 高波动日仍具 shape 可用性
- 风险时段不出现系统性失真

## 8. 综合评分建议

为避免单一指标主导，建议引入综合评分 **Composite Score** 作为正式排序依据。

### 8.1 DA 综合评分

\[
\mathrm{Score}_{DA} = 0.25 \cdot \mathrm{MAE}_{norm} + 0.30 \cdot (1 - \mathrm{profile\_corr}) + 0.20 \cdot \mathrm{neg\_corr}_{norm} + 0.15 \cdot \mathrm{amp\_err}_{norm} + 0.10 \cdot (1 - \mathrm{direction\_acc})
\]

**说明：**

- DA 更重视整日轮廓，因此 `profile_corr` 权重最高
- `neg_corr_day_ratio` 用于控制「方向性灾难」

### 8.2 RT 综合评分

\[
\mathrm{Score}_{RT} = 0.30 \cdot \mathrm{MAE}_{norm} + 0.20 \cdot (1 - \mathrm{profile\_corr}) + 0.20 \cdot \mathrm{neg\_corr}_{norm} + 0.20 \cdot \mathrm{amp\_err}_{norm} + 0.10 \cdot (1 - \mathrm{direction\_acc})
\]

**说明：**

- RT 保留较高的点误差权重
- 但 amplitude 与 neg_corr 的重要性同样较高

（注：式中 `*_norm` 表示对各指标在评测集或历史基线上做归一化后的可比标度，具体归一化方式由公司评测流水线统一约定。）

## 10. 最小可执行版本要求

若当前阶段不便一次引入全部指标，建议至少保留以下 6 个正式指标：

1. MAE  
2. profile_corr  
3. neg_corr_day_ratio  
4. amplitude_err  
5. direction_acc  
6. composite_score  

并强制按以下三类场景分组：

- 典型日  
- 高波动日  
- 异常日 / 极端日  

这可作为公司内部第一版统一评估口径。

## 11. 使用建议

### 11.1 不允许仅以 MAE 决定模型优劣

若某模型 MAE 最优，但 `profile_corr`、`amplitude_err`、`neg_corr_day_ratio` 明显较差，则不得认定为最佳模型。

### 11.2 新模型必须同时报告主指标和分场景结果

任何新模型提交评审时，必须附带：

- 主评估表  
- 分场景评估表  
- 结构评估表  

### 11.3 模型选择必须服务业务目标

若业务重点是：

- 曲线轮廓识别  
- 储能充放窗口判断  
- 峰谷时段排序  

则应优先选择 shape 更优的模型，而非单纯 MAE 最低模型。

## 12. 结论

电价预测模型的评价，不应再停留在「整体误差是否更小」，而应升级为：

- 价格水平是否正确  
- 曲线形状是否相似  
- 振幅是否合理  
- 关键峰谷是否正确  
- 在异常场景下是否仍然稳定可用  

本标准建议将 **MAE + Profile Correlation + Negative-Correlation Day Ratio + Amplitude Error + Direction Accuracy + Composite Score** 作为正式评估主体系，并结合典型日、高波动日、异常日分组进行统一评审。

只有同时满足上述要求的模型，才可认为具备真实业务可用性。

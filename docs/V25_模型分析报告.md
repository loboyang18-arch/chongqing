## 2. 模型结构

### 2.1 总体思路

V25 在 **V24 特征矩阵** 上，沿用 V18 的「**15 分钟多通道张量 × 7 日回看 × 逐小时样本**」范式：每个目标小时一条样本、**每次前向只预测 1 个电价标量**（24 小时即 24 次前向再拼成日曲线）。骨干将原 V18 的 3 层 `Conv2dPriceNet` 换为 **10 层卷积 + 3 个残差块** 的 `ResConv2dPriceNet`。推荐配置启用 **双头**：同时回归小时绝对电价与相邻小时价差（delta）。

```text
输入张量 (B, C, H, W)
  C = C_TOTAL = 34（V24 直接模式、无天气；以 patch 后训练日志为准）
  H = H_SLOTS = 24（默认 5+0：预测时刻前 5h、后 0h，共 6 小时 × 4 槽/小时）
  W = 7（回看日历日）

       ┌─ Stem Conv 64 ─┐
       │  ResBlock 64   │×1  (L2-L3 残差)
       ├─ MaxPool(2,1) ─┤
       │  Conv 64→128   │
       │  ResBlock 128  │×2  (L5-L6、L7-L8 残差)
       ├─ MaxPool(2,1) ─┤
       │  Conv 128→64   │×2 (k=3,p=0 收缩)
       └─ Flatten ──────┘
              │
    ┌─────────┴─────────┐
 price_head (FC)    delta_head (FC)   ← 仅 DualHead 版本
    │                   │
  小时电价预测        小时价差预测
```

### 2.2 网络层次（10 个 Conv 层）

| 阶段 | 层 | 说明 |
|------|-----|------|
| L1 | Stem | `Conv2d(C_in→64, k=3, pad=1)` + BN + GELU |
| L2-L3 | Res64 | `_ResBlock(64)`：Conv-BN-GELU-Conv-BN + skip |
| — | Pool1 | `MaxPool2d((2,1))`，时间维减半 |
| L4 | Trans | `Conv2d(64→128)` + BN + GELU |
| L5-L6 | Res128a | `_ResBlock(128)` |
| L7-L8 | Res128b | `_ResBlock(128)` |
| — | Pool2 | `MaxPool2d((2,1))` |
| L9-L10 | Final | 两层 `Conv2d`（128→64→64，`padding=0` 收缩空间） |
| Head | FC | Flatten → Linear(→128) → GELU → Dropout → Linear(→1) |

**参数量**（`DualHeadResConv2dPriceNet`，`C_TOTAL=34`, `H_SLOTS=24`, `dropout=0.44`）：约 **969,154**（双头各一套 price/delta 全连接头，共享骨干；dropout 影响 head 宽度，参数量略有变化）。

### 2.3 双头结构（推荐 5+0 配置）

类名：`DualHeadResConv2dPriceNet`（`V25_DUAL=1`）

- **price_head**：预测归一化空间中的小时 **绝对电价**，推理时反标准化为 元/MWh。
- **delta_head**：预测相邻小时 **价差** \(\Delta_t = P_t - P_{t-1}\)（训练标签由 V18 数据集构造）。
- **损失**（训练时）：

\[
\mathcal{L} = \mathrm{L1}(P_{pred}, P_{true}) + \lambda \cdot \mathrm{L1}(\Delta_{pred}, \Delta_{true})
\]

**推荐**用 `V25_DELTA_LAMBDA` 控制 \(\lambda\)（默认 **0.2**）；`run_v25_resconv` 旧路径仍可读 `V18_DELTA_LAMBDA`。

### 2.4 与 V18 原版 Conv 的差异

| 维度 | V18 `Conv2dPriceNet` | V25 `ResConv2dPriceNet` |
|------|----------------------|-------------------------|
| 卷积层数 | 3 | **10** |
| 残差连接 | 无 | **3 处**（64 通道 1 块，128 通道 2 块） |
| 通道宽度 | 64 为主 | 64 → 128 → 64 |
| 特征来源 | 默认 DWS/`build_feature_matrix` | **V24 `sql_data` 30 列市场特征** |
| 双头 | 可选（同 V18 补丁） | 推荐启用 |

## 3. 输入与输出

### 3.1 输入特征（V24 直接模式，默认）

数据文件：[`sql_data/chongqing_market_join.csv`](../sql_data/chongqing_market_join.csv)  
加载逻辑：[`src/model_v24_da.py`](../src/model_v24_da.py) → `load_sql_feature_matrix()`  
对齐：**15 分钟**索引；通过 V18 的 `dates0 / dates1 / dates2` 映射实现 Lag，无需对整表 shift。

| Lag 级别 | 决策日含义 | 通道构成 | 代表列（节选） |
|----------|------------|----------|----------------|
| **Lag0** | D 日可获知 | 市场列 + 4 维时间编码 | `total_gen_pred_v1`, `total_load_pred_v1`, … |
| **Lag1** | D-1 可获知 | 市场列 | `*_pred_v2`, `market_clearing_price`, `reliability_clearing_*` |
| **Lag2** | D-2 可获知 | 市场列 | `*_actual`, `realtime_clearing_*` |

**`C_TOTAL=34`** = `C_LAG0 + C_LAG1 + C_LAG2`（[`model_v24_da.py`](../src/model_v24_da.py) 直接 patch 后；无天气、无 PCA）。

默认 **不启用** 天气列（`V24_USE_WEATHER=0`）、**不做 PCA**（`V24_PCA_COMPONENTS=0`）。  
启用天气时 Lag0 再增加 38 列气象变量。

### 3.2 单样本张量构造（与 V18 相同）

对每个预测日 `d`、每个目标小时 `h`：

1. 取时间窗：默认 **5+0** → `[h-5, …, h]` 共 6 小时 → **24 个 15min 槽**（`H_SLOTS=(5+1+0)×4`）。
2. 在 7 个日历日上堆叠 Lag0/Lag1/Lag2 通道 → 宽 **7 日**。
3. 得到张量形状 **`(C_TOTAL, 24, 7)`**（若用历史 dual02 的 5+1，则为 `(34, 28, 7)`）。

归一化：在**训练日**上对 Lag 通道做 mean/std 标准化；电价标签做 train 集 mean/std 标准化。

### 3.3 输出

| 文件 | 内容 |
|------|------|
| `da_result.csv` | `ts`, `actual`, `predicted`（小时级，测试窗） |
| `seed0.pt` | 训练权重（早停开启时为 val 最优 `seed0_best.pt` 载入后再存盘；末轮模式为最后一 epoch） |
| `v25_norm.npz` | 特征与标签归一化参数（`model_v25_train` 路径） |
| `v25_train_history.json` | 每 epoch train/val MAE、profile_corr（`model_v25_train` 路径） |
| `v25_meta.json` | 模型元信息（结构、是否双头、测试指标等） |
| `plots/` | 标准附录可视化（`price_forecast_eval.viz`） |
| `metrics_eval_standard_da_result.json` | 标准指标 JSON |

**权重策略**（`V25_EARLY_STOP`）：

- **`1`（默认）**：验证 MAE 改善则写入 `seed0_best.pt`，早停后加载最优；最终另存 `seed0.pt`。
- **`0`**：跑满 `V25_EPOCHS`，**使用最后一轮权重**（dropout 网格采用）。

**注意**：`V25_DROPOUT` 在 `import model_v25_train` 时会快照一次；入口脚本应在 import 前 `export V25_DROPOUT=...`。训练循环内通过 `_v25_dropout()` 再读环境变量，避免被 import 顺序覆盖。

## 6. 结果解读与优缺点

### 6.1 优势

1. **多源市场特征**：V24 SQL 特征将日前计划、出清、可靠性、实时出清等分层 lag 对齐，信息密度高于纯 DWS 序列。
2. **残差深网**：10 层 Conv + 残差缓解退化，较 V18 明显改进 shape 与 MAE。
3. **双头监督**：λ=0.2 时联合约束水平与一阶变化，利于跟踪日内起伏。
4. **工程成熟**：复用 V18 数据管线、评估与 `run_v25_resconv.py` 一键训练+评估。

### 6.2 局限与风险

1. **两套训练入口**：`run_v25_resconv` 仍用 `V18_*` 默认（含 5+1）；与 `model_v25_train` 的 `V25_*` 默认（5+0）易混淆，实验需统一入口。
2. **末轮 vs 早停**：网格最优用末轮；早停 14d val 实验曾出现最优 epoch 过早、测试 MAE 变差。
3. **验证窗长度敏感**：7 天 / 14 天 val 切换需同时改 `SPLIT_*`；调参易过拟合验证集。
3. **极端周失效**：3 月底～4 月初部分日期 MAE 极高，需规则或分层模型兜底。
4. **依赖 sql_data 质量与覆盖**：特征矩阵需与 DWS/市场数据同步更新。
5. **可解释性弱于 LGB**：不如 V12 便于做特征重要度分析。

### 6.3 改进方向（建议）

| 方向 | 说明 |
|------|------|
| 固定 `V25_DROPOUT=0.44` + 早停重试 | 在末轮最优附近看 val-best 是否更稳 |
| 扩大验证窗 / 时间序列 CV | 降低 val 偶然性 |
| 针对灾难周做样本加权或分场景模型 | 抑制 3/31 类失效（场景路由实验见工程笔记，未纳入本报告） |
| λ 与 ctx 在 5+0 下重搜 | λ=0.3 曾略优 MAE；BEFORE 网格见 §5.6 |
| 与 Moirai 表征 stacking | 已有 `moirai_stack_lgb`，未超 V25，可作集成尝试 |

# 重庆电价预测项目 — 模型实验与工程汇总报告

**文档版本**：2026-03-30  
**范围**：以 V16d（小时结算价 Transformer）为主线，延伸至 V12 对照、V17 日级多步输出、云端训练与自动化对比脚本。

---

## 1. 业务与建模目标

- **预测对象**：官方小时级 **日前结算价** `settlement_da_price`（V16d 主线），与 V12 使用的 **15 分钟级 `target_da_clearing_price`**（表格特征 + Point LGB）为不同任务定义，指标不宜简单横比数值，仅可作趋势参考。
- **评价优先级**（与用户约定一致）：日内形状（`profile_corr`）→ 振幅 → 峰谷时刻 → 逐点 MAE。
- **核心矛盾**：训练期与测试期分布偏移明显；神经网络在「纯序列」与「强表格特征」下的过拟合表现差异大。

---

## 2. 数据与特征管线（简述）

- **序列输入**：`build_feature_matrix()`（[`src/model_v16_nhits.py`](../src/model_v16_nhits.py)）对齐 15 分钟网格，含 `HIST_COLS` / `FUTR_COLS`，目标在 V16d 中为小时 `settlement_da_price` 对齐到整点样本。
- **V12 表格特征**：[`output/feature_da.csv`](../output/feature_da.csv)，由 [`src/feature_engineering.py`](../src/feature_engineering.py) 等流程生成；**样本为小时级**（一日 24 点），非 15 分钟逐点预测表。
- **工程特征去价格列实验**：从 242 维中剔除名称含 `price/clearing/settlement/bid_price` 的列，约余 204 维，减轻 D-2 价格锚定带来的过拟合。

---

## 3. V16d：小时结算价 Transformer（主线）

### 3.1 模型与训练特点

- **结构**：对齐双轴滑窗 + Patch Transformer（[`src/model_v16d_hourly_settlement.py`](../src/model_v16d_hourly_settlement.py)）。
- **设备**：已支持 **CUDA 优先**，其次 MPS，再次 CPU；DataLoader 在 CUDA 下默认 `pin_memory` 与多 worker（可用 `V16D_DL_NUM_WORKERS` 覆盖）。
- **训练策略**：训练段与验证段合并训练、固定 epoch；测试集指标仅作监控（存在信息泄漏风险，不宜单独作为调参唯一依据）。
- **异常样本**：可对训练集过滤 `settlement_da_price < 200` 的「炸点」样本（`OUTLIER_FLOOR`）；实验表明过滤后训练更好拟合，但测试 `profile_corr` 可能略降，说明极端样本仍含泛化信息。

### 3.2 主要实验结论（来自历史跑数与对话记录）

| 方向 | 现象 |
|------|------|
| **加大容量**（d_model / dim_ff / nlayers） | 测试集 `test_pcorr` 在已测范围内仍随容量上升，未见明显饱和。 |
| **拼接 V12 全量工程特征** | 训练集拟合显著变好，但测试集 MAE 与 `profile_corr` 变差，过拟合加剧。 |
| **工程特征去掉价格列** | 相对「含价格工程特征」明显缓解过拟合（测试 MAE 下降），但仍未优于**纯序列**大模型配置。 |
| **拉长 epoch（如 500）** | 训练集 `train_pcorr` 可继续升高；测试集有小幅 MAE 改善，`profile_corr` 提升有限，边际收益递减。 |

### 3.3 可复现入口脚本

| 脚本 | 说明 |
|------|------|
| [`run_v16d_large_engfeat_noprice.py`](../run_v16d_large_engfeat_noprice.py) | 大模型 + 去价格工程特征；`V16D_EPOCHS`（默认 500）、`V16D_BS`、`V16D_D_MODEL` 等环境变量可调；`V16D_OUT_DIR` 可固定输出目录。 |
| [`run_v16d_scale_noengfeat.py`](../run_v16d_scale_noengfeat.py) | **纯序列**，不读 `feature_da.csv`；同样支持上述缩放环境变量。 |
| [`run_gpu.sh`](../run_gpu.sh) / [`run_gpu_noengfeat.sh`](../run_gpu_noengfeat.sh) | 云端一键启动（先打印 CUDA 信息）。 |
| [`run_v16d_noengfeat_sweep.py`](../run_v16d_noengfeat_sweep.py) + [`run_gpu_v16_sweep.sh`](../run_gpu_v16_sweep.sh) | **三组容量 × 多种子**自动对比，输出 `detail_per_seed.csv` 与 `summary_by_config.csv`，便于按 `test_pcorr_median` / `test_amp_err_mean` 选配置。 |

## 4. V12：Point LGB 与「充分训练」对照

- **脚本**：[`run_v12_point_full_train.py`](../run_v12_point_full_train.py)  
  - 无早停，满轮 boosting（默认 `NUM_BOOST_ROUND=3000`，可用 `V16_POINT_ROUNDS` 环境变量覆盖）。  
  - 输出按轮数分子目录：`output/v12_point_full_train/r{轮数}/`。
- **结论要点**：继续增加 LightGBM 轮数可显著压低训练 MAE、抬高训练 `profile_corr`（例如万轮量级可达 ~0.98）；测试集在过长训练下 `profile_corr` 反而变差，属典型过拟合。
- **与 V16 对比**：表格 + LGB 在训练集上极易「吃透」；Transformer 在同数据定义下更吃容量与 epoch，但测试端仍受分布偏移制约。

## 5. V17：日级样本 → 24 点输出（探索分支）

- **脚本**：[`run_v17_day24_transformer.py`](../run_v17_day24_transformer.py)，[`run_gpu_day24.sh`](../run_gpu_day24.sh)。
- **输入**：过去 `V17_PAST_DAYS×24` 小时的历史通道 + 目标日 24 小时 `FUTR_COLS`；标签为当日 24 点 `settlement_da_price`。
- **曾修复问题**：标签曾被与特征一同 z-score 后再标准化，导致**重复归一化**与输出异常；已改为 `raw_target` 单列标签只归一化一次（已 push）。
- **多起点训练**：`V17_TRAIN_ANCHOR_STRIDE_H=1` 时每天 24 个锚点，显著增加有效训练样本；评估仍可用 `V17_EVAL_ANCHOR_STRIDE_H=24` 对齐「每日 00:00 起算的日曲线」报告。
- **训练稳定性**：日样本极少时 batch 与 `drop_last` 会强烈影响每 epoch 更新步数；已将 `drop_last=False`；日志中 `train/test` 指标建议与多起点/评估集划分一致解读。

## 6. 指标说明（避免误读）

- **`profile_corr`**（[`src/shape_metrics.py`](../src/shape_metrics.py)）：按**日历日**切分，仅保留**恰好 24 个点**的完整日，对每日算 Pearson 相关，再对日取**平均**（非整条序列一个相关系数）。
- **V16d 日志中的 `train_pcorr` / `test_pcorr`**：与上述日级 `profile_corr` 定义一致（小时整点、24 点/日）。

## 7. 工程与云端部署

- **路径约定**：[`src/config.py`](../src/config.py) 中 `SOURCE_DIR`、`OUTPUT_DIR`；大数据不入 git，`source_data/` 与 `output/` 产物需单独同步（如 `scripts/package_v16d_data.sh` 打 tar）。
- **GitHub + PAI-DSW**：代码 push 后云端 `git clone` / `git pull`；训练建议 `nohup ... > log 2>&1 &` 防断线。
- **进程数偏多**：CUDA 下 DataLoader 默认多 worker，同一条 `run_v16d_noengfeat_sweep.py` 下可见多个 `python` 子进程；可用 `export V16D_DL_NUM_WORKERS=0` 减少进程数。
- **部署说明文档**：[`docs/PAI_DSW_DEPLOY.md`](PAI_DSW_DEPLOY.md)。

## 8. 综合结论与建议路线

1. **短期主力**：继续打磨 **V16d 纯序列**（`run_v16d_scale_noengfeat.py` + sweep），用 `summary_by_config.csv` 在多 seed 下选稳健配置，而不是单次大 epoch。
2. **表格特征**：全量或去价格工程特征在 Transformer 上均易过拟合；若再用，建议极强正则、降维或与 LGB 级联，而非简单拼接进 point 分支。
3. **V17**：适合作为「多步直接预测」试验田；与 V16 相比任务更难（一次 24 维输出），需配合 loss/锚点策略继续迭代。
4. **V12**：仍是强基线；`run_v12_point_full_train.py` 用于观察训练集饱和与过拟合边界。
